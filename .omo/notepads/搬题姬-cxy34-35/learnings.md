## 关键经验

### 1. mv 与 write 并行竞争陷阱（踩坑！）
并行调用 bash(mv) + write(新路径文件) 时，write 工具若先创建了目标目录，`mv src dst` 会把 src **嵌套进** dst 而非改名。症状：`work_cxy0035/` 出现在 `work_cxy0035_箱子和球/` 内部。
**教训**：目录更名 mv 与写文件必须串行，或 mv 前先确保目标不存在。本任务在 cxy0035 中踩中，靠移动子目录文件 + rm 修复。

### 2. mkin.h 随机生成器死循环陷阱（踩坑！）
out_ops 最初用"随机重试直到 cnt[x]>0"选 x，x 偏置 [1,10] 时 1..10 球被拿光 → 无限重试，mkdata 挂死。
**教训**：有约束的随机生成器必须维护有球盒子集合（set<int> alive），从 alive 中选 x，O(log n) 更新。70% 偏置 + 30% 全范围回退。

### 3. 手工操作序列必须验证约束（踩坑！）
case 19 模式 (1 2)(2 3)(2 1) 循环：手工推演时误算 cnt2 收支，实际每轮 cnt2 净 -1，第二轮就断球（cnt 变负）。
**教训**：每设计一组手工序列，用独立脚本（Python 参考实现）验证：①全部约束合法 ②答案与标程一致。本任务最终用独立 Python 实现 25/25 核对通过才放行。

### 4. epoch 技术优化集合清空
cxy0035 标程用 epoch 标记数组实现集合 S 的清空（epoch++ O(1)），避免每次 O(n) 清空数组导致 O(nm)。case 11（(1 2)(2 1) 交替 5e4 次 → 5e4 次清空）与 case 19（(1 2)(2 3)(3 1) 循环 → 33334 次清空）专门击穿 O(n) 清空实现。std 0.02s 跑完 1e5 操作。

### 5. score 修正：大 N 效率思维 +100
cxy0035 初评 1300，审计时发现需效率思维（避免 O(nm) 集合清空，有专门 hack 数据）→ 按 03-gesp.md 6.2 数据规模修正 +100 → 1400。cxy0034 解法 O(N) 读入即答、无效率设计空间，不加。

### 6. 清理与打包
- mkdata 运行完自动 rm std；手动 rm mkdata 残留。
- 比赛搬运禁生单题 zip，直接 zip -r 合集 work_*/；打包前 rm -f work_*/*.zip 防嵌套。
- unzip -l 验证：grep -c "\.zip$" = 0（无嵌套）、两题目录在 zip 根下、每题 50 个 testdata 文件。
